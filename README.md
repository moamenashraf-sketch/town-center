# Town Center — site and tenant ad pages

Static bilingual (AR/EN) pages for Town Center, Al Arid, Riyadh (developed by Blacksand).

- **`/`** (`index.html`, `style.css`, `thank-you.html`): the original brochure-style page. Untouched by the ad pages.
- **`/lp/`** and **`/lp/en/`**: tenant-leasing ad pages (generic master + 6 categories), generated by `build.ps1`.

## Ad pages: how it works

```
categories.json        every per-category field (headline, sub, bullets, image, form value, meta, OG)
units.json             available units (TODO rows until Blacksand sends the list; [] hides the section)
lp/config.js           runtime config: form endpoint, tracking IDs, direct-contact flag (public file)
lp-src/template.html   the one page template
lp-src/lp.css, lp.js   page CSS and JS (copied to lp/ by the build)
build.ps1              generator (PowerShell 5.1+, no dependencies)
tools/make-images.ps1  resizes /assets photos into /assets/lp (hero 1000x750, OG 1200x630)
lp/**/index.html       BUILD OUTPUT, committed so GitHub Pages serves it. Do not edit by hand.
404.html               unknown /lp/... URLs fall back to the master page
```

Build (from the repo root, Windows PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

Commit the regenerated `lp/` folder. The build overwrites pages but never deletes: if you rename or remove a category, delete its old folders under `lp/` and `lp/en/` by hand.

### Example UTM links (barbershop; swap the slug per ad set)

```
Meta:      /lp/barbershop/?utm_source=meta&utm_medium=paid_social&utm_campaign=tenants_barbershop&utm_content={{ad.name}}
Snapchat:  /lp/barbershop/?utm_source=snapchat&utm_medium=paid_social&utm_campaign=tenants_barbershop&utm_content={{ad.name}}&sc_click_id={{SC_CLICK_ID}}
Google:    /lp/barbershop/?utm_source=google&utm_medium=cpc&utm_campaign=tenants_barbershop&utm_term={keyword}&utm_content={creative}
LinkedIn:  /lp/barbershop/?utm_source=linkedin&utm_medium=paid_social&utm_campaign=tenants_barbershop&utm_content=%%AD_ID%%
```

`gclid`, `fbclid` and `sc_click_id` are picked up automatically from the URL. The macros above are placeholders: use each platform's own macro syntax. UTM values are stored in `sessionStorage` and sent with the form.

## Add a category

Edit only `categories.json`: copy an object in `categories[]`, change `slug`, `label`, `formValue` (the dropdown value), `image` (a key of `images`), `headline`, `sub`, `bullets` (keys of `bulletLibrary`, or `{ "ar": "...", "en": "..." }`), `metaTitle`, `metaDescription`. Then run the build. The category appears in the "who we're looking for" strip and the form dropdown on every page. To use a new photo: add it under `images`, add it to `tools/make-images.ps1`, run that script, then build.

## Tracking and the form (`lp/config.js`)

Nothing loads and nothing is sent while a value is empty.

| Key | Purpose |
|---|---|
| `FORM_ENDPOINT` | JSON `POST` target. Empty = marked demo thank-you, nothing sent. |
| `GTM_ID` | If set, only GTM loads and the direct snippets are skipped (no double firing). |
| `GA4_ID`, `GADS_ID` + `GADS_LABEL`, `META_PIXEL_ID`, `SNAP_PIXEL_ID`, `LINKEDIN_ID` (+ optional `LINKEDIN_CONVERSION_ID`) | Direct snippets, used only when `GTM_ID` is empty. |
| `SHOW_DIRECT_CONTACT` | Default `false`. When `true`, shows phone/email in the footer; clicks push `contact_click`. |

`dataLayer` events: `lp_view` (category, language), `cta_click`, `form_start`, `form_submit_success` (category, branches, opening, `event_id`). Direct mode fires GA4 `generate_lead`, Google Ads conversion, Meta `Lead` (same `event_id`, for Conversions API de-duplication), Snap `SIGN_UP`, LinkedIn conversion. No name, phone or other personal data is ever sent to a pixel.

Form payload (JSON): name, mobile (normalised to `+9665XXXXXXXX`), business, category, branches, area, opening, cr, message, `consent_contact`, UTM/click IDs, `landing_slug`, `language`, `event_id`, `page_url`, `submitted_at`. Consent is a required, un-ticked checkbox.
